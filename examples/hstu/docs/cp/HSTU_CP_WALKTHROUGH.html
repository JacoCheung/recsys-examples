func cache hit on layer 2..N

The step=2 func tensor was already built by layer 0 of this HSTUBlock.forward for this cu_seqlens. Layers 1..N-1 hit the cached entry (hstu_attn_cp.py:282-285). Across training steps that cycle the same cu_seqlens values, every call after the first iteration is a hit (block comment hstu_attn_cp.py:152-169).

Step 6 — fp32 cast → gather to global

The fp32 accumulator is cast back to the input dtype (hstu_attn_cp.py:1279), returning a (12, H, D) bf16 tensor on each rank. Each rank scatters its 12 rows into a globally-shaped zeros buffer via local_to_global, then SUM-all-reduce gathers all contributions (each global row owned by exactly one rank → SUM is identity). The implementation is gather_jagged_from_cp_rank at hstu_attn_cp.py:591-622; the test driver does the same at test_cp_forward.py:159-165. 

out_local_bf16 = out_local.to(q_local.dtype)   # (12, H, D)

# scatter into (48, H, D) zeros buffer
contrib = zeros((48, H, D), dtype=fp32)
contrib[local_to_global] = out_local_bf16.float()
dist.all_reduce(contrib, op=SUM, group=cp_group)

out_global = contrib.to(bf16)                  # shape (48, H, D)

Step 7 — Backward begins: re-run forward ring on saved KV

The autograd Function saves q, k, v, cu_seqlens_q, cu_seqlens_k (hstu_attn_cp.py:2005). _HSTUVarlenCPFunc.backward (hstu_attn_cp.py:2034) calls _multi_gpu_backward_arbitrary (hstu_attn_cp.py:1709) which re-runs the **same forward** ring direction so each step's KV matches what forward saw. The kernel-bwd is called directly via _call_hstu_bwd_kernel (hstu_attn_cp.py:1300) — bypassing _per_tile_partial_grads's replay-forward (which costs ~80 ms / step on cw-dfw round-5; hstu_attn_cp.py:1296-1298).

Why the func cache is critical here

Backward runs on a PyTorch autograd worker thread, NOT the forward thread. A threading.local() cache would be invisible to this thread and force localize_func_for_cp_step to rebuild every layer × ring step. That was the cw-dfw round-4 regression (hstu_attn_cp.py:160-174); the module-level dict at hstu_attn_cp.py:183 is pinned by test_func_cache.py:test_cache_visible_from_other_thread.

Step 9 — Final dQ / dK / dV global view

The fp32 accumulators are cast back to the input dtype (hstu_attn_cp.py:1881-1885) and returned as (dq, dk, dv) from _multi_gpu_backward_arbitrary. _HSTUVarlenCPFunc.backward packages those into the autograd return tuple along with Nones for every non-tensor argument (hstu_attn_cp.py:2063-2079). The trainer then sees per-rank gradients in DualChunkSwap order; its DDP / FSDP / TP all-reduce plumbing handles the cross-replica accumulation.
